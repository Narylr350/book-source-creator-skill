## 主要变化

- Browser MCP 现在是站点分析的必需能力。初始化后，第一项站点操作是打开用户提供的目标 URL，并从浏览器页面、交互和网络请求完成搜索、详情、目录、正文四链路取证。
- 站点检查直接进入 `assess`，不再保留独立 probe 阶段、`probe_site`、`--fast` 或 HTTP fallback。
- `init` 和 `run` 会返回结构化的 `requiredCapability`，缺少 Browser MCP 时明确进入安装或配置流程。
- `deliver` 仍是唯一最终交付审计入口，局部 HTTP、Browser 或 Android 结果不会被当作完整交付结论。

## Validator 与 Android 修复

- 修复页面声明小写 `charset="utf-8"` 时触发错误二次转码的问题，避免中文正文被替换成 `?`。
- 增加小写 UTF-8 自动检测和显式 charset 回归测试。
- 增加 Gradle Windows 中文路径兼容配置，测试和构建不再依赖临时盘符或复制到 ASCII 目录。
- Validator 改为使用系统分配的本地端口，并由 CLI 统一启动、探活和停止，避免固定端口冲突和残留进程干扰后续任务。
- Android 模拟器会根据电脑的 HTTP 代理或 TUN 环境同步全局代理；无法映射的网络环境会明确阻塞，不再把设备网络超时误判为站点失败。
- Android Probe 启动会区分匿名验证与登录验证。匿名站点不会创建登录待办；存在登录特征时仍要求真实 Cookie 证据。
- `android` 单入口会把显式 `--keyword` 和 `--book-url` 传给 validator，避免依赖文本推断验证参数。

## 发布流程

- 版本 tag 推送后会自动运行测试、构建 Validator 和 Android Probe、打包 ZIP，并使用本文件创建 GitHub Release。
- 手动运行 Release workflow 只生成可下载的测试 artifact，不会发布 GitHub Release。

## 升级说明

- 旧版 run-state 与当前工作流不兼容。升级后对目标站点重新运行 `init`，不要复用旧 run 目录。
- 运行书源生成任务前需要配置可导航、获取 snapshot 和检查网络请求的 Browser MCP。
- 本项目不提供书源合集、小说内容，也不绕过验证码、付费墙、Cloudflare、DRM 或其他访问控制。
